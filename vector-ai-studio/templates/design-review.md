# 设计盲评表（design-review）

用途：给「这个标识好不好」留一份可归档的人类判断。**AI 不填这张表。** AI 可以生成盲评包（`python scripts/studio.py --review-pack ...`）、可以做几何与统计测量，但五个维度的分数只能由人写。

## 评审前

1. 只拿 `output/<run-id>/review/case-XX.svg`、`output/<run-id>/review/case-XX.png` 与本表；不要打开 `output/<run-id>/review/key.json`。
2. 先看 16px 缩略图 3 秒，再看大图；顺序不要倒过来。
3. 每件先写一句「它想说什么」，再看这句话是否成立。

## 评分（每维 0–2，锚点见 `references/design-language.md` 第 10 节）

| case | 概念 | 层级 | 比例 | 细节 | 耐久 | 一句话理由 |
|---|---|---|---|---|---|---|
| case-01 |  |  |  |  |  |  |
| case-02 |  |  |  |  |  |  |
| case-03 |  |  |  |  |  |  |

概念维只评「主张能否一句话说清」，不评「是否符合需求」：盲评不给 brief，评审人没有判断需求符合度的依据。需求符合度由甲方在开包后对照 brief 单独判，另立记录，不并入总分。

## 否决项（任一命中即整件不通过，与分数无关）

- 单色或 16px 下结构消失。
- 含位图、渐变、投影，或无法在目标引擎中落地。
- 与需求原文相悖（漏掉必备元素、出现明确不要的东西）——由甲方在开包后对照 brief 判，评审人不判。

## 结论写法

- `通过`：五维均 ≥1 且总分 ≥7，且无否决项。
- `有条件通过`：总分 ≥6，列出一条必须修的项。
- `不通过`：其余，写明最主要的一条原因。

## 归档

评审完成后，把本表与 `output/<run-id>/review/key.json`、`output/<run-id>/review/review-sheet.csv` 一起存到运行目录。没有 `output/<run-id>/review/key.json` 的评审表无法追溯是哪一版设计，不能作为质量证据。
