# vector-ai-studio 发布说明

> 一句话：把一句自然语言需求，变成一份**按机械判据达到质量阈值、可继续编辑的原生 `.ai`**。
> 格式落地是底线，不是卖点；能不能用取决于出图质量闭环是否真的闭合。

## 一、装了之后你会得到什么

- 一份原生可编辑 `.ai`（Illustrator `saveAs()` 产出，非 SVG 改后缀、非 PDF 容器冒充）
- 一份与 `.ai` 实际外观一致的 PNG 预览（由 Illustrator 自身导出，不是几何近似）
- 一份机器可读验收日志 `acceptance.json`（A–F 六维分数、轮次、H1–H4 硬门禁、降级标记）
- 一份对外交付说明 `delivery-note.md`

## 二、安装与自检

```
# 解压后进入技能根目录
python scripts/selftest.py --fixtures --log-dir <RUN_DIR>
python scripts/run_fixtures.py
python scripts/detect_deps.py --json
```

预期结果分两种，取决于是否装了 VectorCraft 引擎——**两种都不算失败，但退出码不同，请别把 3 当成 1 看**：

| 环境 | `selftest --fixtures` | `run_fixtures` |
|---|---|---|
| 装了 VectorCraft CLI | **32 passed / 0 failed / 0 skipped**，`status=ok`，**exit 0** | **24/24**，`all_ok=true`，exit 0 |
| 没装 VectorCraft CLI | 30 passed / 0 failed / **2 skipped**（A30、A31 的 VectorCraft 半边），`status=partial`，**exit 3** | 24/24，exit 0 |

`exit 3` 是"部分断言因缺可选依赖未执行"，不是"检查失败"；`aggregate_log.py` 的 H3 仍判通过，
前提是跳过的**全部**是可选项——一旦跳过项里混进非可选项，H3 会指名失败。
纯脚本层零外部依赖，无论哪种环境都必能跑起来。

依赖只有三件，都会先探测再降级，不会静默跳过：

| 依赖 | 缺失后果 |
|---|---|
| Adobe Illustrator + COM | 无法产出原生 `.ai` → H1 不达标，L4 降级 |
| PowerShell | COM 桥不可用 → 同上 |
| 第三方 SVG 渲染器 | **不需要**。Illustrator 自带导出即可产出忠实预览 |

第 3 行值得单独说：早期版本把「Illustrator 导出」写死成 `MISSING` 从不尝试，导致无渲染器的机器只能退回内置兜底——而内置兜底会把圆画成方块。现在候选链第 4 位真的会调 Illustrator，因此只要能产出 `.ai`，就必然能产出忠实预览。

## 三、跑一次完整链路

```
python scripts/freeze_spec.py --spec path/to/spec.json --validate --out <RUN>/spec.json
python scripts/sanitize_svg.py --in path/to/draft.svg --out <RUN>/final.svg
python scripts/render_png.py --in <RUN>/final.svg --out <RUN>/preview.png
python scripts/land_ai.py --svg <RUN>/final.svg --out <RUN> --deps <RUN>/deps.json
python scripts/score.py --svg <RUN>/final.svg --judge <RUN>/judge.json --spec <RUN>/spec.json --out <RUN>/score.json
python scripts/batch_check.py --runs-dir <RUNS> --out <RUN>/batch.json
python scripts/aggregate_log.py --run-dir <RUN> --run-id <ID>
```

三条容易踩的：

1. **H3 的取证文件必须在运行目录内**。`selftest.py` 要带 `--log-dir <RUN_DIR>`，否则 `acceptance.json` 找不到它，`h3` 恒不通过。
2. **达标需要 F**。F 是「多个独立 run 的批量稳定性」，至少要 3 个 run 汇总进 `batch.json`（`f_verified=true`）。单个 run 跑得再漂亮也只能到「不达标」。
3. **产物写在包外**：`~/.vector-ai-studio/output/`，可用 `VECTOR_AI_STUDIO_OUT` 覆盖。技能包内不留任何运行期文件。

## 四、这套东西如何避免「看起来达标、其实很烂」

这是本项目全部返修的主线。四层闸：

| 闸 | 机制 |
|---|---|
| 判据机械计算 | A–F 六维由脚本按 `config/thresholds.json` 数值比较得出，LLM 不得宣布成绩 |
| 反伪造 | L2（读图能力缺失）时 A/B 必须记 `N/A (capability_missing)`，出现数字即 `E-FABRICATED-SCORE`；被顶掉的数字转存 `discarded_scores` 留审计 |
| 预览保真度 | 兜底渲染的预览必须机械判定 `fidelity`；非 `faithful` 自动转 L2，**字段缺失按 `limited` 处理**（fail-closed，不给省略字段留后门） |
| 记分完整性 | 受评日志必须带全必需维 `{A,B,C,D,F}`，**达标日志还须带 `E` 且 `A/B/C/D` 为计分 dict**；缺任一键即 `E-NO-SCORE` |

**为什么第四层要单独存在**：删掉一个键，就能让「这一维判 0」这条不利证据消失；而删键后的日志在旧校验器下会静默通过。这类造假不制造错误结论，只让不利事实看不见——比出错更难发现。

第三条是本轮最重的修复：原实现下，真机冒烟是 `builtin-fallback`（圆被画成方块）却给出 `A=2 / B=2 优秀`、`capability_missing=false`。也就是说——**技能在看一张失真图，然后给语义和构图打满分**。

## 六、已知问题（不阻断交付，如实列出）

| 编号 | 问题 | 影响 |
|---|---|---|
| P2-a | 直调 `aggregate_log.py` 不传 `--run-id` 时 `run_id` 为空串（冒烟与正常链路均有值） | 手工直调时日志不可追溯；契约文档未夸称派生能力 |
| P2-b | 自检项 A8 的「双运行时一致性」实为**同一 Python 二进制、两种运行模式**（默认 vs `-I` 隔离 + `--pycache_prefix` 重定向），不是两个不同版本的解释器；`default_vs_isolated_equal=True` 仅表示这两种模式结果一致 | 跨 Python 版本一致性**未取证**。若被读成「跨解释器/跨版本一致」属过度解读 |
| P2-c | `SKILL.md` 正文无 `fidelity` 字样（行为在正文描述、字段定义在 `references/pipeline-contract.md`） | 分层文档，查字段需跳契约 |
| P2-d | 可选增强依赖（PyYAML / cairosvg）在本机均未安装，A8 中「有该依赖」的两个分支因此**未实测** | 属环境限制，非实现缺陷；如实标注而非声称已覆盖 |
| P2-f | `--profile print` 的 CMYK 只做到「原生对象颜色逐个转换」（实测 5 个对象），**PDF 兼容层未写入 DeviceCMYK**（实测 `/DeviceCMYK` 0 处、`/DeviceRGB` 1 处；可解码内容流中 `rg`/`RG` 算子存在、`k`/`K` 为 0）；`embedICCProfile=true` 也未产生 `/ICCBased` | 印刷交付不能只看清单的 `save_options`，必须看 `observed.device_cmyk`；该差异会出现在 `unverified` 字段里，不会被静默略过。印刷件仍建议用 Illustrator 另存 PDF/X 或由印厂转换 |
| P2-g | **VectorCraft 产物的文字，在 Illustrator 里会变成轮廓**：实测同一份文件在 VectorCraft 中 `kinds.Type=2`（文字对象与字体都在），在 Illustrator 中 `textFrames=0`、`pathItems` 增加 22。**能否改字取决于客户用哪个软件打开** | 以 Illustrator 为交付环境时请改走 Illustrator 引擎保住活字。清单 `warnings` 会写明这一条 |
| P2-h | **VectorCraft 会替换本机缺失的字体**（实测 Helvetica → Source Sans 3）。工具本身会报 warning，清单也照抄进 `warnings` 与 `source_probe.fonts`，**不是静默的** | 字形与你设计的不同；交付前请核对 `source_probe.fonts` 里的 `missing` 标记 |
| P2-i | **VectorCraft 引擎的图层不可靠**：单元素 `<g>` 会生成命名图层，多子元素的组实测塌成 1 层；触发条件未定位 | 清单层数取自文件 `/OCGs`，是实测值；需分层交付时请核对 |
| P2-j | **VectorCraft 引擎的 CMYK 无输出意图**：内容流为 `k/K`、`/DeviceCMYK` 为 0（未声明即 DeviceCMYK），但无 `/OutputIntent` 与 `/ICCBased` | 是 CMYK、不是 PDF/X，印刷条件未声明。Illustrator 引擎则相反：能出出血但出不了 CMYK |
| P2-k | **两个引擎都没有 PDF 出血框**：Illustrator 引擎做了画板扩大与 8 条矢量裁切线，但产出的 PDF 里 TrimBox 与 BleedBox 相等；VectorCraft 引擎无此能力 | 需要符合印刷规范的出血时，请用 Illustrator 的 PDF/X 预设导出，或由印厂处理 |

| P2-e | `--validate-case` 对达标日志只校验「`E` 键是否存在、`A/B/C/D` 是否为计分 dict」，**不校验 `E` 分值与达标结论的一致性**：手改文档写 `grade=达标` + `E=0` 仍会通过校验 | 只在手工篡改日志时可达。真实链路 `score.py` 必写 `E:"N/A"` 或计分 dict，产不出该组合；本项取舍是为了不复制 §7.3 的 E 分支、避免与单一事实源打架 |

修任何一条都要动已冻结的包并重跑终验，而三者都不阻断交付、也不使判据不可信——因此决定带着这份清单发布，而不是修完之后声称完美。

### 交付档位与交付清单（v1.1）

落地时先声明客户要什么，不要用默认值赌：

```
--profile screen    屏幕交付（默认）
--profile print     印刷：请求 ICC + 逐对象转 CMYK + 3mm 出血与 8 条裁切线
--profile handoff   客户改稿：顶层分组建成命名图层
```

单项可覆盖：`--compat` / `--pdf-compatible` / `--embed-icc` / `--cmyk` / `--bleed-mm` / `--layers-from-groups`。
**所有保存选项都显式写入 `IllustratorSaveOptions`**——`pdfCompatible` 官方默认恰好为真、`embedICCProfile` 恰好为假，靠默认值等于把交付质量交给安装环境。

落地成功后额外产出 `deliverable.json`：一份**给客户核对**的清单，与验收日志分开。验收日志评价「好不好」，交付清单只记录「是什么」——色彩空间、ICC、出血、图层、字体、位图、画板 pt/mm、sha256，以及必须说明的风险（第三方重存会剥离 `AIPrivateData`、CMYK 未做色彩管理等）。

其中 `unverified` 字段专门记录**「要求了但没兑现」**。例如要求转 CMYK 而 PDF 兼容层仍写 RGB 时，这一条会出现在那里；工具不会因为命令返回成功就宣称完成。

字段契约已落成 JSON Schema（`references/schemas/`），可用零依赖的 `scripts/schema_check.py` 独立校验；错误码集中在 `references/error-codes.md`，由自检双向强制与代码一致。

## 六之二、两条引擎，能力不同

落地 `.ai` 有两条路，产出同一套产物与同一份交付清单，`engine` 字段记录实际用的是哪条。

| | Illustrator 引擎（`land_ai.py`） | VectorCraft 引擎（`land_vc.py`） |
|---|---|---|
| 前提 | Windows + Illustrator + COM | 只需 `vectorcraft-cli`，跨平台、无 COM |
| 单次耗时 | 约 20 秒（含冷启动） | 约 0.3 秒 |
| 文字 | **保留活字** | **转成轮廓**（不可改字） |
| 图层 | 可按组生成 | 单元素组可，多子元素组塌成 1 层 |
| CMYK | **做不到**（PDF 层始终 RGB） | **能做**（内容流 `k/K`、`documentColorSpace=CMYK`） |
| 输出意图 / PDF/X | 可另存 PDF/X（含输出意图） | 无 `/OutputIntent`，不是 PDF/X |
| 出血 | 扩画板 + 裁切线（三框相等，非真出血） | 不支持 |

**怎么选**：含文字的字标走 Illustrator 保活字；纯图形、要 CMYK 的走 VectorCraft。这条分工不是偏好，是上表实测出来的。

## 七、它不做什么

- 不承诺一次直出即达标。达不到就是「不达标」，没有第三种说法。
- 不假设装了 Illustrator 就能无人值守：COM 不可驱动时走半自动，由用户在本机执行一次脚本，日志强制标 `semi-manual`。
- 不做位图、照片级真实感、3D、像素级修图；不做已有 SVG 的纯格式转换；**不做纯格式考据与可行性调研**——最后这条是硬性反向边界，写在 `description_zh` / `description_en` 里。
