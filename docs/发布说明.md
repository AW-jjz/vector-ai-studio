# vector-ai-studio 发布说明

> 一句话：把一句自然语言需求，变成一份**按可断言判据给出可复核质量结论、可继续编辑的 VectorCraft PDF 兼容 `.ai`**。
> 格式落地是底线，不是卖点；能不能用取决于出图质量闭环是否真的闭合。

> **状态 A 提示（r70）**：引用 `grade=达标` 前须自行复核三项——① `final.ai` 是否为真 `%PDF-` 且能重新打开；② `structure_readback.json` 的 `paths` 与产物是否对得上；③ `selftest.json` 是否为本次运行产生。本包不作为「审美已被验证」「印刷合规」「两名不同真人已看过」的对外证据。

## 一、装了之后你会得到什么

- 一份 VectorCraft PDF 兼容 `.ai`（由 VectorCraft CLI 产出，并用 `info` 重开回读对象计数；不是把 SVG/PDF 改后缀；产物不写 Adobe 私有编辑数据，格式属性见 §六已知限制）
- 一份与 `final.svg` 同源的 PNG 预览（缺真实渲染器时用内置兜底，保真度由 `render_png.py` 自己判定，非 `faithful` 自动转 L2）
- 一份机器可读验收日志 `acceptance.json`（A–F 六维分数、轮次、H1–H4 硬门禁、降级标记）
- 一份交付清单 `deliverable.json`（只记录从产物字节实测的事实与未兑现项）
- 一份对外交付说明 `delivery-note.md`


## 三、跑一次完整链路

```
python scripts/freeze_spec.py --spec path/to/spec.json --validate --out <RUN>/spec.json
python scripts/sanitize_svg.py --in path/to/draft.svg --out <RUN>/final.svg
python scripts/render_png.py --in <RUN>/final.svg --out <RUN>/preview.png
python scripts/conformance.py --svg <RUN>/final.svg --rules path/to/conformance.json --out <RUN>/conformance.json
python scripts/land_vc.py --svg <RUN>/final.svg --out <RUN> --profile print
python scripts/score.py --svg <RUN>/final.svg --judge <RUN>/judge.json --spec <RUN>/spec.json --out <RUN>/score.json
python scripts/batch_check.py --runs-dir <RUNS> --out <RUN>/batch.json
python scripts/aggregate_log.py --run-dir <RUN> --run-id <ID>
```

也可以压成一条：`python scripts/studio.py --spec ... --svg ... --out <RUN>`。

三条容易踩的：

1. **H3 的取证文件必须在运行目录内**。`selftest.py` 要带 `--log-dir <RUN_DIR>`，否则 `acceptance.json` 找不到它，`h3` 恒不通过。
2. **达标需要 F**。F 是「多个独立 run 的批量稳定性」，至少要 3 个 run 汇总进 `batch.json`（`f_verified=true`）。单个 run 跑得再漂亮也只能到「不达标」。
3. **产物写在包外**：`~/.vector-ai-studio/output/`，可用 `VECTOR_AI_STUDIO_OUT` 覆盖。技能包内不留任何运行期文件。

## 四、这套东西如何避免「看起来达标、其实很烂」

这是本项目全部返修的主线。四层闸：

| 闸 | 机制 |
|---|---|
| 判据机械计算 | A–F 六维由脚本按 `config/thresholds.json` 数值比较得出，LLM 不得宣布成绩 |
| 反伪造 | L2（读图能力缺失）时 A/B 必须记 `N/A (capability_missing)`，出现数字即 `E-FABRICATED-SCORE`；被顶掉的数字转存 `discarded_scores` 留审计 |
| 预览保真度 | 兜底渲染的预览必须机械判定 `fidelity`；非 `faithful` 自动转 L2，**字段缺失按 `limited` 处理**（fail-closed，不给省略字段留后门） |
| 记分完整性 | 受评日志必须带全必需维 `{A,B,C,D,F}`，**达标日志还须带 `E` 且 `A/B/C/D` 为计分 dict**；缺任一键即 `E-NO-SCORE` |

**为什么第四层要单独存在**：删掉一个键，就能让「这一维判 0」这条不利证据消失；而删键后的日志在旧校验器下会静默通过。这类造假不制造错误结论，只让不利事实看不见——比出错更难发现。

第三条是本轮最重的修复：原实现下，真机冒烟是 `builtin-fallback`（圆被画成方块）却给出 `A=2 / B=2 优秀`、`capability_missing=false`。也就是说——**技能在看一张失真图，然后给语义和构图打满分**。

## 四之二、C 维现在到底测什么（r20 起）

以前 C 维只有一条：`len(colors) <= N`。**数颜色个数不是色彩质量**——一张全用同一支灰的画，和一张九个不相干饱和色硬凑的画，在这条判据下可能同分。

现在拆成三件互不相同的事，**分开报告，绝不揉成一个「色彩分」**——揉在一起就看不出是哪一件坏了：

| 问题 | 用什么 | 为什么是它 |
|---|---|---|
| 两个色是不是同一个色 | CIEDE2000 < 2.3 | 这是**小色差**问题，ΔE00 正是为小色差拟合的 |
| 声明要区分的色真拉开了吗 | HyAB < 10 | 这是**大色差**问题，此时 ΔE00 会失真（Abasi 等 2020） |
| 前景/背景读得出来吗 | WCAG 2.1 对比度 + 三种色觉缺陷模拟取最小值 | 见下 |

**为什么值得加**：`#FF0000` 在黑底上，WCAG 判 **5.25，通过 AA**；红色盲视角只有 **1.26**，几乎看不见。而「黑底红字」是最常见的默认强调色搭配。这条判据不是为了更严格，是为了让**一类看不见的失败**变得可见。

**作用域是刻意收窄的，这一点比阈值更重要。** WCAG 2.1 SC 1.4.11 原文只约束
"parts of graphics **required to understand the content**"，并明确豁免装饰性图形。
所以只有 spec 里**显式声明** `contrast_pairs` 时才检查；未声明记 `not_applicable`，
全部声明为 `decorative` 记 **`exempt`** 而**不是 `pass`**——「没比较过任何阈值」不能显示成「通过」。

**色觉缺陷这一层是本项目扩展，不是标准。** WCAG 完全不要求模拟色觉缺陷，所以
`cvd_contrast_floor` 在配置里标注的是「无标准依据、未标定」。同理，重复色的 2.3 出自
`looks-same` 的一个常量，而该常量原本描述的是 ΔE*ab、不是 ΔE00，**出处未坐实**；
显著差异的 10.0 干脆没有任何出处。**配置里每个数字旁边都写着它站不站得住**。

**这一版只测量、不判失败。** 三个阈值都没经过分布校准，拿未标定的数字当闸门，
等于把噪声点成红灯。所有发现进入 `perceptual_warnings` 与 `acceptance.json`，
**看得见，但不改变结论**。要升级为硬门禁，必须先附「≥N 样本的分布 + 校准记录」。

### 交付档位与交付清单（v1.1）

```
--profile screen    屏幕交付（默认）
```

单项可覆盖：`--compat` / `--pdf-compatible` / `--embed-icc` / `--cmyk` / `--bleed-mm` / `--layers-from-groups`。

落地成功后额外产出 `deliverable.json`：一份**给客户核对**的清单，与验收日志分开。验收日志评价「好不好」，交付清单只记录「是什么」——色彩空间、ICC、出血、图层、字体、位图、画板 pt/mm、sha256，以及必须说明的风险（第三方重存会剥离 `AIPrivateData`、CMYK 未做色彩管理等）。

其中 `unverified` 字段专门记录**「要求了但没兑现」**。例如要求转 CMYK 而 PDF 兼容层仍写 RGB 时，这一条会出现在那里；工具不会因为命令返回成功就宣称完成。

字段契约已落成 JSON Schema（`references/schemas/`），可用零依赖的 `scripts/schema_check.py` 独立校验；错误码集中在 `references/error-codes.md`，由自检双向强制与代码一致。

## 七、它不做什么

- 不承诺一次直出即达标。达不到就是「不达标」，没有第三种说法。

## 八、路线 B / C：照片转印刷件，以及纯 Craft 产线（v1.1.0 新增）

### 路线 B：客户给了一张照片，要印刷件

照片把摄影棚的灯"焙"进了像素。`scripts/delight.py` 先把光照拉平（主体掩膜 + 低频除法），
`scripts/trace_ref.py` 再矢量化，`scripts/export_print.py` 按成品尺寸 / dpi / 出血出印刷件。

**确定性契约**：「近白像素是纸背景还是物体内部高光」从颜色、连通性、局部形状都判不出来——
桥接高光、轴向缝、斜缝、曲线缝、细长高光互为反例。脚本因此不再猜：不给 `--mask` 时只对
明显有色/暗的像素去光照，**所有近白像素逐字节保持不变**；要高光去眩光必须提供主体掩膜。
五种几何形态（轴向缝 / 斜缝 / 曲线缝 / 细长高光 / 桥接高光）验证近白零改动，任何从像素推
掩膜的启发式都被禁止。

### 路线 C：只用 VectorCraft，不依赖 Adobe

`scripts/land_craft.py` 与 land_ai 脚本同输出契约，但整条链只用 VectorCraft CLI：
无 COM、无 Windows 依赖、无 Adobe 授权。print 档走真 CMYK 转换 → 文档出血 →
PDF/X-1a / X-3 / X-4 导出（TrimBox / BleedBox / MediaBox、裁切与套准标记、色标、
页面信息、内嵌输出意图、字体内嵌）。H1 用 CLI 的 info 命令重开 .ai 独立读回。

> **PDF/X 合规限定（r70）**：代码侧自洽 —— `pdfX1a/X3/X4`、`--bleed-mm 3.0`、`/TrimBox` 与 `/OutputIntent` 检查均实存；**PDF/X 规范原文未核**（iso.org / pdfa.org / Adobe 帮助页 403/404，检索日 2026-11-11）。本链路不作为印厂合规依据，交付印厂前请按 PDF/X 规范自行复核 OutputIntent / 色彩空间 / TrimBox / BleedBox。

**已知限制**：VectorCraft 写 PDF 兼容 .ai 与 legacy v7 .ai，不写 Adobe 的 AIPrivateData；
handoff 档 .ai 保留 SVG 分组；PDF/X-1a 未标签 DeviceCMYK 属规范行为；引擎仍是 alpha
（GitHub storytold/vectorcraft，MIT / Apache-2.0，锁定版本，关键行为已做成断言 A46）。

### 为什么默认推荐路线 C

Adobe 官方说明 Creative Cloud 服务未在中国大陆的 adobe.com 上开放，自动化产线
不应把落地绑在桌面程序上。路线 C 无 COM、无 Windows 依赖、跨平台 headless，
且与旧 Adobe 路线在输出意图上的**实测差异**为：VectorCraft 侧 PDF/X-1a 有输出意图与 CMYK 落色，旧 Adobe 路线 `ICCBased=0` 且
无 OutputIntent 是硬限制）。

## 十二、r38（2026-11-10）：第 28 轮 QA 的 Q1–Q5

**动因**：第 28 轮记的 Q1–Q5 当时判"可进下一轮"，其中 Q1/Q2 是**实测失败**——
不是没测到，是测错了数；Q3 更隐蔽：漏测之后报出来的形态是"没有流可测"，
与"干净跑完且没有算子"长得一样。

**改了什么**
- **Q1 内联图像终点靠扫 ` EI ` 猜**：r37 用 `[\s\x00]EI(?=\s|$)` 找终点，
  可位图样本里完全可能出现这两个字节。一旦命中，图层被提前切断，**样本余下的字节**
  回到算子统计里（QA 实测 k=2，真值 1）。现在先读 `BI` 字典：有 `/L` 用 `/L`，
  否则按 `/W × /H × /BPC × 分量数(CS)` 算出字节数，跳到 `after = ID + size` 再找 `EI`。
  字符串剥除也挪到切段之后——先剥再切会让样本里每个 `(...)` 改变后续所有偏移。
- **Q2 `/BI` 被当成内联图像开始**：`/BI` 是名字，不是 `BI` 算子。旧正则
  只排除单词字符，于是从 `/BI` 一路跳到下一个 ` EI `，把中间的 `k` 吞掉（实测 k=0，真值 1）。
  现在两道限制：lookbehind 排除 `/`，且 `BI` 之后必须是 `/键名`。
  **M2a 是这一点的对照**：只去掉 lookbehind、保留白名单时仍然是绿的——
  说明是两层守护，不是一层写了没用。
- **Q3 对象流 `/N` 偏小就静默漏测**：旧代码按 `/N` 截断配对表。页字典若落在被截掉的
  那一对里，整个文件连一个 `/Type /Page` 都找不到，于是报"0 个页面流、0 个算子"。
  现在按**实际对数**读，并在 `warnings` 记一条 `/N` 与实读不一致。
- **Q3 的语义修正**：`content_streams.objects` 原来写的是 `/Contents` **引用数**，
  引用指向一个没解开的对象时，读者看不出"引用了几条"和"找到几条"的差别。
  现在 `objects` = 实际找到的流数，新增 `refs` = 引用数。

**conformance 现在读 `style=""`。** 之前只读 presentation attribute（继承那一层是前几轮补的，行内 `style` 一直没读），带 `style="stroke-width:10"` 的文件会被判成「没有描边、没有宽度」。新增 `inline()` 解析行内声明，`prop()` 从元素向父元素逐级取，取不到再看属性；同元素上 `style` 压过属性，这是 CSS 级联里 author 声明压 UA 提示的顺序；显式 `none` 让继承链在此终止，而不是继续向上找。`<style>` 样式表仍不解析——不做选择器匹配，只把它出现的次数记进 `measured.style_sheets`，宁可报告「有几个样式表没应用」，也不假装已经应用。
